# recipedb-board

Board UI for [recipedb](https://github.com/simpsonbm1/recipedb) — a searchable database of
recipes extracted from the cooking videos the owner's wife shares over Messenger.

## This repository is PUBLIC and contains NO DATA

**Never commit recipe content here — no recipes, no `index.json`, no thumbnails, no inbox
notes, no screenshots of real recipes.** This repo holds only the HTML/CSS/JS shell. The
`.gitignore` blocks the obvious paths as a guard rail, but the rule is the point.

The reason for the split: GitHub Pages cannot serve a site from a private repository on a
personal Free account, and paying does not fix it — publishing a Pages site *privately*
requires an organization on GitHub Enterprise Cloud. So the page itself must be public, and
the private recipe data is fetched at runtime instead of being built in.

## What's in here

| File | Purpose |
|---|---|
| `index.html` | The whole app — tokens, styles, and logic inline. No build step. |
| `sw.js` | Service worker. Caches the shell **only**; never touches `api.github.com`. |
| `manifest.webmanifest`, `icon.svg` | PWA install metadata. |

Run it locally with any static server (`py -m http.server 8323`) — `file://` will not work,
because the service worker and the API layer both need an http origin.

## How it works

The page asks once for a fine-grained personal access token scoped to the `recipedb`
repository (Contents: read/write) and keeps it in `localStorage`. It then:

- **reads the recipe list** from `recipes/index.json` in the private repo — one fetch, not
  one per recipe. That index is committed there and regenerated by the `rdb` CLI on every
  add; it is safe to commit because `rdb` on a real machine is its only writer (unlike
  worktracker's board.json, which two writers share and so cannot be committed).
- **reads a recipe** on tap, parsing the record's markdown into ingredients/steps/source.
- **writes a queue entry** to `inbox/` when you paste a link — the board's only write, and
  the only thing it ever does to the private repo besides read.

No server, no backend; the data never passes through this repository. The token stays on
your device and can reach nothing but that one repo; revoke it any time from GitHub →
Settings → Developer settings → Personal access tokens.

Design: the "Organic / Warm cards" direction from `design_handoff_recipe_board/` in the
private repo. Sibling of `worktracker-board`; the GitHub API layer is modelled on it.
